# AWQ W4A16 Decision Log

## Decision

Use `AWQ W4A16` as the main weight-only quantization path. Keep the `BF16`
baseline path as the required control for fair comparison.

## Candidate Options

- `BF16 baseline`: required unquantized control path.
- `AWQ W4A16`: activation-aware weight-only quantization with 4-bit weights and 16-bit activations.
- `W8A16`: possible placeholder comparison with weaker compression.
- `GPTQ`: possible placeholder comparison, but not implemented in this step.

## Evaluation Dimensions

- Alignment with the project weight-quantization scope.
- Expected memory and bandwidth reduction.
- Accuracy-retention risk for OCR and fine-grained localization samples.
- Scope risk for the current low-risk mainline.
- Ability to compare against BF16 without touching unrelated layers.

## Final Choice

`AWQ W4A16` is the main planned method because it is weight-only, matches the
project documentation, and has clearer expected memory and bandwidth upside than
`W8A16`. Compared with starting from `GPTQ`, AWQ gives a cleaner low-risk story
because it emphasizes activation-aware protection of important channels.

## Deferred Options

- `W8A16` may be kept as a configuration placeholder later, but no full flow is implemented here.
- `GPTQ` may be kept as a configuration placeholder later, but no full flow is implemented here.
- `KIVI`, `KVQuant`, `SmoothQuant`, `QAT`, structured pruning, and visual token pruning are out of scope for this weight-quantization step.

## Evidence Boundary

No AWQ model artifact has been generated by this step. No accuracy, TTFT,
throughput, memory, or bandwidth improvement is claimed until a real BF16
baseline vs AWQ benchmark exists.
